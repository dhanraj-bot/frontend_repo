# CLAUDE.md

Guidance for working in this repository.

## What this project is

**Shadcn Admin Dashboard** — an admin dashboard UI built with Shadcn UI and Vite. It is a responsive, accessible, RTL-capable collection of dashboard pages and components meant to be reused as a starting point for admin/back-office applications.

This particular checkout is the "powerlook admin" workspace; the app itself lives in the `shadcn-admin/` subdirectory and tracks the upstream project `github.com/satnaing/shadcn-admin`.

### Why it exists / background

The original author built dashboard UIs repeatedly for work and personal projects, and wanted a reusable collection of dashboard UI. Some components are custom; many are adapted from official ShadcnUI examples. Several Shadcn components have been modified — mainly for RTL (right-to-left) language support. It is a front-end-only UI layer (no real backend); data fetching is wired through TanStack Query and Axios, with mock/faker data in `data/` folders.

## Tech stack

- **Framework:** React 19 + TypeScript
- **Build tool:** Vite
- **Routing:** TanStack Router (file-based, auto code-splitting; routes generated into `src/routeTree.gen.ts`)
- **Data/server state:** TanStack Query (React Query) + Axios
- **Client state:** Zustand (`src/stores/`)
- **UI:** Shadcn UI (TailwindCSS v4 + Radix UI), Lucide + Tabler (brand) icons
- **Forms/validation:** react-hook-form + Zod
- **Tables:** TanStack Table
- **Auth (partial):** Clerk — there is both a custom token-based auth flow and a Clerk-based flow under `src/routes/clerk/`
- **Tooling:** ESLint, Prettier (with import sorting + Tailwind class sorting), Knip (unused-code detection)
- **Testing:** Vitest in **browser mode** via Playwright (Chromium)

## Commands

Run all commands from the `shadcn-admin/` directory. The repo uses **pnpm** (see `pnpm-lock.yaml`).

```bash
pnpm install                # install deps
pnpm dev                    # start Vite dev server
pnpm build                  # tsc -b && vite build
pnpm preview                # preview production build
pnpm lint                   # eslint .
pnpm format                 # prettier --write .
pnpm format:check           # prettier --check .
pnpm knip                   # find unused files/exports/deps
pnpm test                   # vitest run (headless browser)
pnpm test:watch             # vitest watch (headless)
pnpm test:ui                # vitest UI
pnpm test:coverage          # coverage report
pnpm test:browser:install   # install Playwright Chromium (first-time setup)
```

## Project structure

```
src/
  main.tsx              # App entry: QueryClient + Router + Theme/Font/Direction providers
  routeTree.gen.ts      # AUTO-GENERATED by TanStack Router — do not edit by hand
  routes/               # File-based routes
    __root.tsx          # Root route
    _authenticated/     # Protected routes (dashboard, users, tasks, chats, apps, settings, help-center)
    (auth)/             # Sign-in, sign-up, OTP, forgot-password
    (errors)/           # 401 / 403 / 404 / 500 / 503 pages
    clerk/              # Clerk-based auth + user-management variant
  features/             # Feature modules (apps, auth, chats, dashboard, errors, settings, tasks, users)
                        #   each with components/ and data/ (mock data) subfolders
  components/
    ui/                 # Shadcn primitives (some customized for RTL — see README)
    data-table/         # Reusable TanStack Table building blocks
    layout/             # App shell: sidebar, header, etc.
  context/              # Theme, font, direction (RTL), layout, search providers
  stores/               # Zustand stores (e.g. auth-store.ts)
  hooks/                # Shared hooks
  lib/                  # utils, cookies, server-error handling, etc.
  config/               # App config
  styles/               # index.css (Tailwind entry)
  test-utils/           # Test helpers
```

Path alias: `@/` → `src/` (configured in `vite.config.ts` and `tsconfig`).

## Conventions & important notes

- **Routing is file-based.** Add/rename files under `src/routes/` — the router plugin regenerates `routeTree.gen.ts` on dev/build. Never edit that file manually.
- **Two auth paths exist.** The default flow uses a custom token stored in a cookie via the Zustand `auth-store` (`src/stores/auth-store.ts`); a parallel Clerk flow lives under `src/routes/clerk/`. `VITE_CLERK_PUBLISHABLE_KEY` is the only env var (see `.env.example`).
- **Query error handling is centralized** in `main.tsx`: 401 resets auth and redirects to `/sign-in`; 500 redirects to `/500` (prod only); see `src/lib/handle-server-error.ts`.
- **RTL support is a first-class concern.** Several `src/components/ui/` components are intentionally modified from upstream Shadcn for RTL. Before regenerating a UI component via `npx shadcn@latest add <component>`, check the README's list of "Modified" / "RTL Updated" components and merge manually to avoid clobbering customizations.
- **Tests run in a real browser** (Playwright/Chromium), not jsdom. Test files are colocated (`*.test.ts(x)`). Run `pnpm test:browser:install` once before the first test run.
- **Formatting is enforced:** Prettier sorts imports (`@trivago/prettier-plugin-sort-imports`) and Tailwind classes. Run `pnpm format` before committing.
- **Commits** follow Conventional Commits (`cz.yaml`); recent history uses `feat/fix/chore/refactor` prefixes.
